## 背景：名称指向对象

`x = 3` 可以理解为把名称 `x` 贴在整数对象 `3` 上。赋值没有声明一个固定类型的“盒子”；类型属于对象，名称可以重新绑定。这个模型能解释参数传递、可变对象和导入行为。

```python
a = [1, 2]
b = a
b.append(3)
assert a == [1, 2, 3]  # 两个名称指向同一个列表

b = [4]
assert a == [1, 2, 3]  # 重新绑定 b，不会修改 a
```

## 问题：选哪种数据结构

| 类型 | 典型用途 | 是否可变 | 关键约束 |
| --- | --- | --- | --- |
| `list` | 有序记录，按位置访问 | 是 | 可重复 |
| `tuple` | 固定长度记录或返回多个值 | 否 | 元素本身仍可能可变 |
| `dict` | 根据键查值 | 是 | 键必须可哈希，键唯一 |
| `set` | 去重与集合运算 | 是 | 元素必须可哈希，无位置索引 |
| `str` | 文本 | 否 | 按 Unicode 字符序列处理 |

“不可变”说的是对象结构不能就地改，并非递归冻结。例如 `([1],)` 是元组，但里面的列表仍能修改。`dict` 保留插入顺序；它的键适合用业务稳定标识，不应靠列表的位置模拟实体身份。

## 条件、循环与推导式

```python
orders = [
    {"id": "A", "amount": 120},
    {"id": "B", "amount": 0},
    {"id": "C", "amount": 80},
]

positive_ids = [row["id"] for row in orders if row["amount"] > 0]
assert positive_ids == ["A", "C"]
```

推导式适合“一次映射，加少量筛选”；出现多层分支、异常处理或副作用时，普通 `for` 循环通常更清楚。空列表、空字典、`0`、`None` 都是假值，但语义不同：检查“没有结果”可用 `if not rows`；检查“确实没有提供参数”应写 `if value is None`。

## 索引、切片与复制

```python
items = [10, 20, 30, 40]
assert items[0] == 10
assert items[-1] == 40
assert items[1:3] == [20, 30]  # 右边界不包含

copy_of_outer = items[:]
```

列表切片得到新的外层列表。若内部元素仍是可变对象，内层对象可能共享；需要完全独立时，先确认数据形状，再考虑 `copy.deepcopy`。不要无条件深拷贝大型数据。

## 数值与业务语义

`float` 适合科学计算和容许误差的场景，不适合把二进制小数的结果直接当成精确金额。财务计算可考虑整数最小货币单位或 `decimal.Decimal`，同时明确舍入规则。

```python
from decimal import Decimal

price = Decimal("19.90")
quantity = 3
assert price * quantity == Decimal("59.70")
```

数字形式的客户编号、邮编等仍是标识，不应求和或平均。这与 [[数据认知框架]] 中的“业务语义”是同一问题。

## 常见误区

- `is` 判断是否为同一个对象；值比较通常用 `==`。与 `None` 比较用 `is None`。
- `list.sort()` 原地排序，返回 `None`；`sorted()` 返回新列表。
- 循环中修改正在遍历的列表可能跳过元素；先构造新列表或明确按索引处理。
- 变量名遮盖 `list`、`dict`、`str` 等内置名称会让后续调用出错。

## 现阶段认知

理解“名称绑定 → 对象可变性 → 数据结构选择”后，很多看似零散的语法陷阱就有共同解释。练习时不要只记输出，先预测**哪些名称指向同一个对象**。
